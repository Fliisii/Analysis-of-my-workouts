# Analysis-of-my-workouts
Аналитика моих тренировок с построением дашборда

🛠 1. Предобработка данных и парсинг (Data Ingestion)
Исходные данные представляли собой сырые текстовые логи тренировок с высокой вариативностью ручного ввода (смесь языков, разные разделители, опечатки).
Для приведения данных к реляционному виду реализован гибкий парсер на re (Regular Expressions), обрабатывающий:
Смену рабочих весов внутри подходов (Smith Machine squats: 50*12 - 50*10 - 55*8).
Дробные веса с плавающей точкой через запятую или двоеточие (12,5: 16-14-12).
Упражнения со своим весом без указания массы (Dips: 20-18-20).
🔍 2. Разведочный анализ (EDA) и обеспечение качества данных (Data Quality)
Вместо базового визуального осмотра был написан автоматический скрипт проверки целостности данных по 10 критическим точкам:
Тип проверки	Логика детекции / Граничные условия	Метод устранения аномалии
Выбросы (Outliers)	Повторения > 34 (физиологический предел для силовых тренировок)	Фильтрация строк (df[df['reps'] <= 34])
Логические ошибки	Совпадение веса и повторений на высоких значениях (weight_kg == reps > 20)	Детекция ошибок ручного ввода, исключение смещения
Ошибки синтаксиса	Наличие символа * при нераспарсившемся значении веса	Удаление некорректных строк лога
Скрытые дубликаты	Полное совпадение полей ['date', 'exercise', 'weight_kg', 'reps']	Выявление 92 избыточных записей для предотвращения bias при расчете объемов
🧠 3. Контекстная импутация и нормализация (Feature Engineering)
Снижение размерности текстовых признаков: Текстовые синонимы и опечатки (например, присяд, squats, smith machine squats, легкий присед) замаплены в единый токен присед. Число уникальных упражнений сокращено до 17 чистых категорий.
Rule-based классификация признаков: Написана функция fix_exercise_by_weight. Если в логе указано размытое «трицепс», алгоритм автоматически категоризирует его как «трицепс в блоке» (при весе > 25 кг) или «трицепс с гантелью» (при весе <= 25 кг).
Восстановление утерянных метрик: Проведен контекстный анализ пропусков — для специфических строк (горизонтальна тяга в блоке макс вес) восстановлен реальный рабочий вес (80 кг) на основе даты и структуры тренировочного блока, что минимизировало объем удаляемых данных.
